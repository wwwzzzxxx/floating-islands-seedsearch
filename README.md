# 浮岛世界神种搜索 · FloatingIslands-Datapack Seed Search

给 [Youmiel/FloatingIslands-Datapack](https://github.com/Youmiel/FloatingIslands-Datapack)（1.18.2 浮岛地形数据包）搜「神种」：

> **穷尽整个 48 位种子空间（281,474,976,710,656 个种子），筛出 1483 个同时满足 5 项农场指标的世界种子。**

> 所以扫完 2⁴⁸ 就等于扫完了「所有可能的结构布局」，剩下的高 16 位是纯赚的——
> 它只影响生物群系，可以事后枚举 65536 个变体去挑群系最好的那个。

## 我们筛了什么（玩家视角）

| # | 条件 | 具体要求 | 干什么用 |
|---|---|---|---|
| 1 | **四联女巫小屋** | 4 个女巫小屋生成点都在 **128 格**半径内，且 4 个都落在 **swamp** 群系 | 单片女巫塔，一份平台吃 4 个屋，产量×4 |
| 2 | **四联海底神殿** | 4 座海底神殿都在 **256 格**半径内，且都在 **ocean** 群系 | 单片海底神殿农场（海绵/海晶灯） |
| 3 | **出生点村庄** | 距原点 **256 格**内有能正常生成的村庄 | 开局有村，不用跑图 |
| 4 | **超大河流群** | 3000×3000 范围内存在大片**连通**河流（最大连通块） | 溺尸塔（三叉戟/铜） |
| 5 | **下界要塞四联路口** | 4000 格内有一个**真要塞**（不是猪灵堡垒）带 **2×2 四联路口** | 凋灵骷髅塔（骷髅头颅） |

几点说明：

- **半径 128 / 256 是社区标准**：128 格内 4 个结构才能被一个农场平台全覆盖。
- **群系条件是硬性的**：女巫小屋只在沼泽生成、海底神殿只在海洋生成，位置对了但群系不对等于没有。
- **「真要塞」很重要**：1.18+ 里猪灵堡垒和要塞用的是**同一套区域参数**，每个区域二选一。
  很多看起来是要塞的位置其实是堡垒（我们第一版就栽在这，见文末「踩过的坑」）。

## 怎么用这些种子

1. 拿到数据包：`EndLikeFloatingIslands-Datapack_1.18.2_v3.7.1.zip`（本仓库附带，md5 `dedd0019365eddb87924a4eedacde4f0`）。
   也可以自己构建：`git clone -b dev https://github.com/Youmiel/FloatingIslands-Datapack.git && pip install chardet && python build.py`。
2. 新建世界 → **更多选项 → 数据包**，把 zip 拖进去启用 → 种子填下表任意一个 → 创建。
   （世界生成类数据包必须在生成前加载，丢进存档文件夹再 `/datapack enable` 会导致出生点区块按原版生成。）
3. 按坐标 tp。**Y 建议先给 200 再往下飞**——浮岛世界下面是虚空。
4. 主世界结构（小屋/神殿/村庄/河流）在**主世界** tp；要塞路口在**下界** tp。

## 复现（给想自己扫的人）

依赖：[cubiomes](https://github.com/Cubitect/cubiomes)（结构位置与群系判定的权威实现）。

```bash
git clone https://github.com/Cubitect/cubiomes.git
# 编译（GPU 版需要 CUDA toolkit；CPU 版用 gcc/clang 即可）
# 注意：cubiomes 的 tests.c 也带 main()，不能整目录 glob，要显式列文件
CUB="biomes.c finders.c generator.c noise.c biomenoise.c quadbase.c util.c layers.c"
cd cubiomes
nvcc -O3 -arch=sm_89 -o ../gpuscan ../src/gpuscan.cu                       # 第一遍：全空间枚举
gcc -O3 -march=native -I. -o ../stage3 ../src/stage3.c $CUB -lm -lpthread   # 变体搜索
gcc -O3 -march=native -I. -o ../stage4 ../src/stage4.c $CUB -lm -lpthread   # 要塞路口
gcc -O3 -march=native -I. -o ../coords ../src/coords.c $CUB -lm -lpthread   # 坐标输出
```

四步流水线：

| 文件 | 作用 | 命令 |
|---|---|---|
| `src/gpuscan.cu` | CUDA 移植 cubiomes 的 quadbase，全空间枚举「女巫小屋四联」位置 base | `./gpuscan -start 0 -count 281474976710656 -hutr 128 -storehut` |
| `src/stage3.c` | 多线程高 16 位变体搜索：小屋/神殿群系 + 村庄 + 河流 | `./stage3 hutbases.txt -offset 6 -t 64 -out valid.txt` |
| `src/stage4.c` | 要塞四联路口（含堡垒互斥过滤） | `./stage4 seeds.txt -range 4000 -out fort.txt` |
| `src/coords.c` | 输出某个种子的全部 tp 坐标 | `./coords <seed> <神殿偏移dx> <神殿偏移dz>` |

## 踩过的坑（复现前必读）

1. **群系互斥（最隐蔽）**：`isQuadBase()` 只检查原点附近 4 个区域，小屋四联和神殿四联会被锚在**同一片 ~1024×1024 区域**里。
   而小屋要沼泽、神殿要海洋——两个群系要求在地理上互斥，184 万个变体全灭。
   **解法**：用 `moveStructure(base, -i, -j)` 把神殿四联的检查平移到别的区域（本例 ±6 区域 ≈ ±3 千米）。
2. **堡垒/要塞互斥**：1.18+ 两者同 salt、同 spacing，每区域位置相同、按群系二选一。
   分析要塞前必须 `applySeed(&g, DIM_NETHER, seed)` 后调 `isViableStructurePos(Fortress, ...)` 过滤，
   否则会把堡垒位置当成要塞（每个种子 ±4000 格内约一半区域是堡垒）。
3. **`Piece.pos` 随旋转变化**：竖向段取 (中x, 端z)、横向段取 (端x, 中z)，跨旋转比较必须用包围盒中心 `(bb0+bb1)/2`。
4. **距离比较**：`d2()` 返回的是**平方**距离，别和开方后的值比；方阵和共线要各用各的跟踪变量，否则会互相覆盖。
5. **「四联」在要塞里很常见**：BRIDGE_CROSSING 是 18×4 的走廊段，沿走廊天然按 19 格等距排列，
   所以「4 个路口成线/成方阵」几乎每个种子都有——这项不构成筛选条件，只是用来挑更好的。

## 数据包对扫描结果的影响（已实测）

- **群系分布、结构位置完全不受数据包影响**：数据包只改 `noise_settings` 的 `final_density`
  （把地形换成 `end_islands + base_3d_noise`，即末地那套），驱动群系的
  `temperature / vegetation / continents / erosion / depth / ridges` 全是原版引用。
  所以 cubiomes 按原版 1.18.2 扫出来的群系和结构坐标**全部有效**。
- **失效的是地形高度类指标**：低 Y 小屋、史莱姆农场（Y<40 无方块）这类依赖实际地形的标准，
  以及结构在浮岛上「落在岛上还是悬空」，只能进游戏验收。

| 项目 | 状态 |

| 结构在浮岛地形上的落地形态 | ⚠️ 待逐种子验收（落在岛上 / 悬空 / 被岛屿切开） |

**给验收者的提示**：tp 的 Y 统一给 200 再往下飞——浮岛世界下面是虚空，直接 tp 结构高度会摔下去。
